# SUKOMBU レビューとリファクタリング

対象: main `a21628b`（M3 Expressive対応統合後）。既存の画面機能とAPI契約を基準に、認証、保存、同期、通知、画面状態、ビルド経路を点検した。

## 確認した問題と対応

| 優先度 | 問題・再現条件 | 対応 |
|---|---|---|
| 高 | BODYログにログインのパスワード・トークン・Authorizationが出力される。リリースでも隠し設定で有効になる | BASICへ変更、Authorizationをredact、エラー本文ログを削除 |
| 高 | 課題・時間割・ニュースがDELETE後に1件ずつ保存され、中断・失敗・並行更新で空または部分的なDBになる | ScombCacheへ保存責務を分離。Roomトランザクションと一括INSERT |
| 高 | 空のHTTPレスポンスを空一覧として扱い既存データを消す | 本文なしはエラー。欠損した課題・不正な期限も既存キャッシュを残して失敗 |
| 高 | 暗号化の失敗を空文字に変換し、ログインが成功扱いになる | 暗号化例外を伝播、tokenとusernameを単一DataStore編集で保存 |
| 高 | ログアウト後もDB・ウィジェット・通知が残り、他のアカウントが旧データを参照できる | Repositoryにセッション境界を集約。ログアウト時に消去、認証前キャッシュ読出し禁止、アカウント変更時のキャッシュ消去、一覧ViewModelも認証変化で初期化 |
| 高 | 一覧から消えた課題や任意の通知タイミングについて古い予約を取り消せない。IDの文字列連結・hashCode衝突もある | 全予約を取消後、全課題から再予約。PendingIntentのdata URIで課題IDと時刻を区別 |
| 高 | バックグラウンドの通知予約処理が権限設定ActivityとToastを直接開く | 自動処理は権限がなければ予約せず終了。設定画面の明示的なテスト操作に権限導線を保持 |
| 中 | セッション切れ・キャンセルを一般例外に変換してWorkerが再試行する | CancellationExceptionを再throw。セッション切れとクライアントエラーは再試行せず、その他は回数制限 |
| 中 | 自動更新がイベントを投げた時点で成功時刻を記録する。購読者がいなければ取得自体が起きない | AutoRefreshManager自身が全データを取得し、成功後だけ時刻を更新。各画面は完了後キャッシュを読む |
| 中 | 課題の更新結果には手動課題が含まれない。時間割更新で手動コマとuserNoteが消える | 保存後のDB一覧を返す。API由来の行だけ削除しローカルのメタデータを保持 |
| 中 | ニュースの古いオブジェクトをREPLACEし、削除済みニュースを復活させる。未読へ戻した状態が更新で失われる | 既存IDのunread列だけUPDATEし、更新時に既存のローカル状態を保持 |
| 中 | 授業の色・メモ・リンクを同時編集すると古いstateで相互に上書きする。複数コマの1件だけを更新する | 編集をMutexで直列化し最新stateから適用。DAOは列単位・科目/学期単位のUPDATE。保存失敗を画面で通知 |
| 中 | アプリ・課題画面・2種類のWorkerで通知やウィジェットの更新責務が分散・重複する | 課題更新成功後の処理へ統一。TaskWidgetUpdaterを共用 |
| 中 | FCM登録が起動直後の未ログイン時に失敗すると、ログイン後に再登録されない | 認証トークンの変化を監視して登録。ServiceのCoroutineScopeを終了時にcancel |
| 中 | 端末のタイムゾーンに依存してScombの締切時刻がずれる。不正な日付を補正して受理する | Asia/Tokyoで厳密に解析し、末尾の余分な文字も拒否 |
| 中 | 起動済みActivityのonNewIntentがComposeの観測対象ではなく、通知タップを取りこぼす | IntentをCompose StateにしてUI側で観測 |
| 低 | 詳細検索の入力語が `-` や `title:` で始まると意図せず演算子になる | 詳細検索フォームからの入力を引用してリテラルとして扱う |
| 低 | DB Singletonのロック内再確認欠落、設定の範囲未検証、署名設定のストリーム未close | 二重チェック、範囲制限、useでclose |
| 低 | CIのcheckoutはマージコミットだが埋め込むSHAはPR先端で一致しない | PR先端を明示checkout。テスト結果をartifactとして保存 |

## 設計判断

- RepositoryはセッションとAPIの一貫性、ScombCacheはDBの原子性とローカル値の保持を担当する。
- APIアクセスとログイン/ログアウトは同じMutexを通す。途中の応答で別アカウントのキャッシュを書き換える競合を防ぐため、通信の並列性より一貫性を優先した。
- 空一覧の取得成功はプロセス内で記録する。再起動後に空一覧を再取得することは許容する。
- セッション期限切れでは認証トークンと通知/ウィジェット表示を無効化するが、同一ユーザーの再認証に備えてローカルDBと所有者情報は保持する。明示ログアウトではキャッシュを消去する。
- UIのM3 Expressiveデザインと既存のAPI/SDK/アプリIDを維持する。

## 残る制約・追加設計が必要な点

1. 既存の破壊的DBマイグレーションは維持している。過去バージョンの全スキーマがないため、推測の移行処理は追加していない。今後のスキーマ変更前にexportSchemaと実データ移行テストが必要。
2. ニュースの既読/未読はローカル優先。既読操作をサーバーへ同期するAPIは実装されていないため、他端末との双方向同期は保証しない。
3. 通知に埋め込む課題URLはAPI取得時のotkeyを含む。期限の仕様と新規キー発行を伴う通知遷移は実機で確認が必要。
4. 学期の切替月・時限のハイライト、科目更新のcustomizedNumberOfCredit=0は既存仕様を維持。大学/API側の契約を確認せず意味を変更していない。
5. 外部のFirebaseプロジェクト設定は維持。独自プロジェクトへの移行だけでは大学からのpushは届かないため、クライアントのみで置き換えられない。
6. Roomの全更新と通知・Glanceは単一トランザクションにはできない。DB更新後に通知やGlanceが失敗した場合はログへ記録し、次の更新で再適用する。
7. 全画面をDB Flow駆動へ移す変更までは行っていない。画面間の即時反映には更新が必要な箇所が残る。

## 検証

12件の回帰テストを追加。Roomの実DBをRobolectricで利用し、INSERT失敗のロールバック、手動データ保持、複数コマ更新、未読保持、削除済みニュースの非復活、セッション消去を確認する。JVMテストではJST解析、不正日付・余分な文字の拒否、検索語のエスケープを確認する。

ローカルではGradle配布元への接続がNetwork is unreachableとなり、ビルド・テストは開始できなかった。`git diff --check`は通過。初回コミット `d251274` は [Android CI](https://github.com/atuy1219/SUKOMBU/actions/runs/34044232173) で `assembleDebug testDebugUnitTest` が成功。最終コミットの結果はPRのAndroid CIを参照。実機でのログイン、Keystore、権限、FCM、通知、GlanceのE2E検証は未実施。
